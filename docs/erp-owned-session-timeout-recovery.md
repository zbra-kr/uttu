## Close-failure P2

In this addendum only, erp_existing_connection.read_existing_daily_once no longer swallows connection.close failure. Success receipt is withheld and EXISTING_CONNECTION_CLOSE_FAILED is raised. Original read_failure_code, phase, safe driver number/class and close_exception_class are retained when both fail. SDK is_closed(), when available, must confirm closure. The outer owned-session reader has equivalent fail-closed cleanup and retains the nested original read diagnostic on outer close failure. No arbitrary foreign-session cleanup is used. Previous real connection already recorded close success; new owned connection closure is also confirmed.

Six focused synthetic cases: native per-call timeout + session confirmation before SELECT; session SET refusal yields no source SELECT/fallback; otherwise successful read with close failure cannot return receipt; simultaneous original read/close failures retain both; outer bound-close failure with successful query; outer query/close failures retain original phase/code. Ruff passes. Previous general/source11/RPC/numeric/concurrency tests are not repeated.
