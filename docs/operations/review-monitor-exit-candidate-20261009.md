# Review exit evidence candidate — NOT ACTIVATED

Problem: the current live review collector can exit nonzero after job_tracker_error / traceback without a review_smart_done marker. The monitor then waits indefinitely. A long live review run itself is not a failure.

Scope: run_daily generates an internal nonsecret daily UUID; the existing flock wrapper emits a correlated collector UUID, wrapper PID/start/executable, lock skip, launch error, and the exact subprocess.call return code. The monitor consumes only this daily UUID and the latest matching launcher attempt. Normal exit records completed, nonzero/signal exit failed, lock contention skipped, launch OSError blocked. No retry, concurrency, lock, child launch command, signal, schedule, notification destination, or permissions change. run_reviews.sh is included unchanged from live for context.

If an identity-verified wrapper disappears or its PID is reused, the monitor waits 60 seconds for delayed exit logging, then settles unknown; this is a log propagation grace period, not a collector execution timeout. It does not infer failure, claim the child stopped, or kill anything. Trusted terminal evidence takes precedence during grace. Current process presence, unreadable logs, missing current-run start, unverified executable/start, and process access errors remain pending; Any probe exception, missing/unreadable log, unconfirmed current launch, log inode replacement, detected truncation/rewrite, or process access uncertainty resets the disappearance grace. Open-file identity is checked against the current path; uncertain replacement during reading also resets it. Grace starts from the monotonic clock sampled AFTER the current process probe, independent of stale monitor-loop wall time, slow detection and wall-clock adjustments. Thus evidence loss/access denial can still leave the monitor waiting; there is deliberately no unconditional elapsed-time failure/deadline.

The wrapper preserves existing subprocess.call and sys.exit semantics and exclusive nonblocking flock. Identity lookup is bounded to 5 seconds and reads ps lstart/comm only, never args. Each evidence record starts with a newline even when actual child stdout has no trailing newline. Evidence uses direct descriptor writes, not buffered print; output failure cannot leave a Python stdout buffer whose shutdown flush changes the child status to 120. Failed output loses evidence, does not launch/retry a child, and does not prove success. Lock-skip text uses the same unbuffered writer. Filesystem lock open/mkdir failures or wrapper interruption may have no terminal marker and can become unknown only with trusted previous identity. Child survival after wrapper death is possible and is not resolved by this candidate. A truncate/refill between polls that is indistinguishable from a normal same-inode prefix-preserving append cannot be identified from these snapshots. Process identity is a local start-time/executable comparison, not a cryptographic identity or proof of content acceptance. Same-second identical executable PID reuse remains a platform identity limit. Plain local log records are not an adversarial tamper-proof audit.
